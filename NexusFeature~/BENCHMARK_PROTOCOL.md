# Benchmark Protocol: Nexus vs Top-3 Unity MCP/CLI Competitors
Дата: 2026-08-31 · Протокол подготовлен для Kiryl / ForkHorizon

Цель: честно измерить, ГДЕ теряется время и за что платит агент, сравнить с топ-3 конкурентами.

## 0. Главный принцип
Сравнивать не «тулы», а ОДИН И ТОТ ЖЕ список сценариев на разных тулах.
Побеждает не тул с меньшим числом, а тул, у которого числа объяснимы.
Холодные/тёплые замеры разделять обязательно.

## 1. Три инструмента для сравнения (MCP-режим)
1. FunplayAI/funplay-unity-mcp — эталон функциональности (156 тулов, execute_code)
2. CoplayDev/unity-mcp — эталон комьюнити (13.8k★, v10)
3. IvanMurzak/Unity-MCP — tools+CLI+runtime (4k★, Apache-2.0)
4. (опционально) официальный Unity CLI — как «пол» скорости, не как конкурент

## 2. Список сценариев C1..C12 (замерять на КАЖДОМ туле)
Матрица: Команда × Число повторов × {холодный, тёплый}

- C1 Подключение: initialize + tools/list (старт → первый ответ)
- C2 Статус: получить текущее состояние редактора
- C3 Прочитать GameObject: полное чтение компонент по имени
- C4 Прочитать сцену: сцена из ≥5 объектов, глубина 3
- C5 Поиск: find_objects / search по имени «Camera»
- C6 Запись лёгкая: создать куб/сферу + удалить
- C7 Запись с компиляцией: создать .cs-скрипт → дождаться компиляции → удалить
- C8 Скриншот Game View: PNG → base64 → вернуть агенту
- C9 Пакетный вызов: 10 read-вызовов одним batch
- C10 Тесты: run tests (EditMode, маленький набор) до результата
- C11 execute_code-эквивалент: произвольный C# в редакторе
  (есть у funplay и Unity CLI eval; Nexus/Coplay/Ivan — пометить «нет»)
- C12 Полный QA-цикл: enter play → click → скриншот → read logs → exit
  (мерить и каждый шаг, и сумму)

## 3. Метрики по каждому сценарию
- A. E2E latency (мс): send → final response
- B. N=10 повторов: p50 / p95 / min / max
- C. Холодный vs тёплый: первый вызов после старта сервера vs медиана
- D. Success rate: доля повторов без error-ответа
- E. Для C7 отдельно: время до «принято» и до «скомпилировано»
- F. Для C8/C12: размер payload в байтах («жирность» ответа)
- G. Bridge overhead = MCP-вызов − raw JSON-RPC той же операции
  (Nexus умеет raw HTTP + мост; у Coplay/Ivan мост — единственный вход)
- H. Стабильность: p95−p50 (джиттер), число ретраев/разрывов за сессию

## 4. Дополнительные оси по каждому инструменту
- Tokens in/out: полный tools/list как текст — символы и ~токены (chars/4)
- Tool count: сколько тулов видит агент после tools/list
- Tool schema avg size: средний размер схемы тула в tools/list
- Payload sizes: типовой read-ответ (get_game_object) в байтах
- Unified return format: {success, message, data} везде или нет

## 5. Фиксация среды
- Одна машина; один Unity-проект на тул (клоны одной сцены); один editor-инстанс за раз
- Между инструментами сравниваем тёплые значения; холодные — отдельно
- Клиент: один и тот же MCP-клиент (Claude Code) и один и тот же промпт
- Записать: модель Mac, Unity-версию, версии пакетов, порты

## 5b. Порядок
- Внутри тула: C1→C12 по порядку, 10 повторов; холодные метрики — первым вызовом
- Между тулами: полный проход одного тула → закрыть Unity → следующий тул

## 6. Nexus: как запускать
- Unity открыт, Window > Nexus Unity → Start Server
- `python3 bench_nexus.py` (уже в папке) — меряет C2–C7, C9 по raw JSON-RPC
  с токеном из Library/NexusUnityAuthToken.txt
- MCP-режим: запустить nexus_unity_bridge.py, подключить Claude Code через .mcp.json,
  повторить те же сценарии через мост
- G (bridge overhead) = MCP latency − raw JSON-RPC latency той же операции

## 7. Форма записи результатов
tool | scenario | cold_ms | p50 | p95 | ok% | payload_B | tokens_tools_list | notes

## 8. Решения, которые должны вытекать из чисел
1. Bridge overhead у Nexus > 2× raw → чинить мост (буферы/ретраи/threading) — дешёвый фикс
2. Raw C3/C4 p50 > 500 мс → проблема main-thread dispatch → фикс в MCPServer
3. C7: «до принято» < 1 с, но «до скомпилировано» доминирует → это domain reload tax,
   лечится только in-memory execute_code → усилить приоритет фичи №1
4. tokens_tools_list у Nexus (14 тулов) < funplay core (34) → подтверждение surface-фикса
5. C12 у funplay покажет, чего реально не хватает Nexus для QA-цикла
6. Субъективное «приятно/нет» после одинакового промпта — записать отдельно

## 9. Anti-goals (не мерить)
- Не мерить «скорость генерации ассетов» — это скорость облака, не тула
- Не мерить число тулов как «крутость»
- Не сравнивать обещания из видео/README
