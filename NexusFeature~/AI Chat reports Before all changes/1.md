## Общие предложения

Все пункты ниже — именно предложения, а не наблюдавшиеся проблемы.

### [SUGGESTION] Автоматически показывать AI, что Nexus доступен

**Проблема:** в реальной работе Nexus не был выбран, несмотря на наличие его конфигурации.

**Доказательство:** [OBSERVED] конфигурация Nexus присутствует, но фактических вызовов нет.

**Идея:** при открытии Unity-проекта показывать краткий список доступных Nexus-действий или явную подсказку:

```text
Unity connected:
- inspect current scene
- run Play Mode test
- read Console
- modify serialized object
- capture Game View
```

**Ожидаемая польза:** меньше риск, что AI полностью обойдёт MCP и продолжит работать только через shell.

### [SUGGESTION] High-level операция «изменить → дождаться Unity → проверить»

Например:

```text
apply scene change
→ wait for compilation
→ wait for domain reload
→ read Console
→ return changed objects and errors
```

**Доказательство:** прямое наблюдение отсутствует; это общая рекомендация на основе Unity workflow.

**Польза:** меньше ручных вызовов и меньше неопределённости о завершении операции.

### [SUGGESTION] Безопасная Unity-верификация после изменения

Одна команда могла бы:

- применить изменение;
- дождаться компиляции;
- проверить Console;
- вернуть diff сцены/объекта;
- сообщить, можно ли безопасно продолжать.

**Доказательство:** [OBSERVED] в текущем workflow после изменения пришлось отдельно запускать сборку и Graphify; Nexus для post-change verification не использовался.
